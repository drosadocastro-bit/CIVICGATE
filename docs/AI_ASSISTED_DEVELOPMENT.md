## How work was governed

**Human direction → AI implementation → testing → AI-assisted review → corrective work → human acceptance.**

The owner set the scope and stop conditions. The implementation agent prepared isolated candidates, used synthetic transports where required, and recorded commands and results. Review examined claims against source and observations. Corrections were versioned where accepted identities had to remain frozen. Human acceptance and permission to publish or execute remained separate decisions.

**Builder ≠ Reviewer ≠ Authority.** Role separation is a working discipline here, not proof of accredited audit independence. The current documentation closeout is an evidence-based builder synthesis for human review, not a newly independent security audit.

## What counts as evidence

- **Model-generated analysis:** explanations, hypotheses and proposed designs; useful but not self-verifying.
- **Tool-executed validation:** commands, JUnit, source hashes and observed state; establishes only the tested scope and environment.
- **Documentary reconciliation:** comparison of recorded artifacts; does not re-execute an experiment or authenticate all claims made by its author.
- **Human authority:** explicit acceptance and bounded permission from the project owner; cannot be supplied by a model's favorable assessment.

Private conversations, credentials, raw model responses and sensitive execution traces are excluded from this public-facing candidate. The [evidence register](GSA_EVIDENCE_REGISTER.md) provides sanitized source identities and clearly labels private sources. AI assistance does not transfer the owner's accountability or eliminate the [known limitations](TECHNICAL_DEBT.md).
